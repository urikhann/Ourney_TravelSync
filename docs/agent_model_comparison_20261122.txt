METHOD
Eight synthetic scenarios x Korean/English x two models = 32 planned turns.
Both models used Groq, the same tools/system prompt/fixture, temperature 0.2,
low reasoning effort, 2048 completion-token cap, six-step/40-second loop limits.
Model order alternated. One repeat, 10 seconds between turns, no rules fallback.
The tools used in-memory fixture places and hours, not the production database.

MANUAL REVIEW
Qwen supplied four accepted proposals: rain (English/Korean), less walking
(English), and unknown hours (English). Its English unknown-hours response
clearly preserved uncertainty. However, its Korean rain reply presented an
indoor guess as definite, which the automated checks missed.
GPT-OSS produced no accepted proposals. Three answered Korean cases (locked,
closed, no_plan) were in English. Its Korean unknown-hours response incorrectly
claimed there was no museum in the current context instead of addressing the
available replacement. An existing separate diagnostic identified malformed
proposal field names in one HTTP-400 case; this does not explain all eight.

INTERPRETATION
Qwen is the stronger candidate in this pilot, particularly for proposing changes.
It is not a validated production winner: 4/16 calls failed with rate limits and
human review found an uncertainty-wording error. GPT-OSS needs tool-schema
compatibility diagnosis before a quality-only comparison. Provider failures
and model quality must be reported separately. No production default was changed.

The automatic score is not an accuracy, feasibility or satisfaction measure.
Latency medians exclude failures. Token counts omit usage not returned with
failed responses and cannot establish billed cost. One repeat is too small for
a reliable general ranking. The saved report remains unchanged.
