Optional evening bars and pubs

In Plan > More options, ?Try to include an evening bar or pub? works like optional
breakfast. It defaults off and automatically chooses a suitable venue; users do
not need to select a specific bar or day. The normal planning submission persists
this preference as daily_composition.evening_enabled.

Retrieval retains up to three evening alternatives per day without displacing the
ordinary meal/activity shortlist, within the existing 60-candidate cap. CP-SAT
prefers a feasible optional evening stop and allows up to one per day. If none
fits, it keeps a valid day without an evening stop and the UI explains the omission.
Existing explicit multi-venue locks remain mandatory and are not silently removed.

Bars/pub categories and alcohol tags define a separate evening role, before
food/cafe classification. They do not count as dinner, cafe or activity variety.
Evening visits must start at 18:00 or later and fit the full visit, return travel,
member availability, known opening intervals/closures and hard exclusions. The
existing unknown-hours policy and warnings remain unchanged. Independent E3
validation checks evening consent, timing and the automatic per-day limit.

Driving planning verifies both the preferred path and a path skipping optional
breakfast/evening visits. A slow or unavailable optional route can therefore be
omitted while keeping a verified feasible schedule. Solver budgets and provider
quotas remain in place. Earlier explicit evening locks can still be removed using
the timeline lock control; turning off the optional preference does not erase them.

The authenticated /evening-choices endpoint remains available for compatibility;
the planning form no longer requires manual venue selection. No catalogue import,
live database change or deployment is part of this UI/planning correction.
